# (2-6) 3차년도 · 성과 리포트 + 운영 콘솔

## 목표
2-2~2-5에서 쌓인 데이터(**행동 로그 · HCI 예측 · A/B 결과 · Optimization Cycle**)를 **조회·관리하는 운영 콘솔**을 구축한다.
대규모 광고 플랫폼 데이터 인프라를 새로 짓는 것이 아니라, **파이프라인 각 단계의 산출물을 집계·시각화·리포팅**하는 수준으로 구현한다.

## 개발 내용
- 2-2 행동·성과 로그, 2-3 HCI 예측·기여요인, 2-4 A/B 결과, 2-5 Optimization Cycle을 집계해 고객사·캠페인·콘텐츠·Variant별 **성과·HCI 지표 대시보드** 제공
- Baseline → 개선 Variant → Winner로 이어지는 **콘텐츠 최적화 이력 조회** (본 콘솔의 핵심 차별점)
- A/B Winner 이력 및 **다음 생성 반영 여부** 추적
- 일간·주간·월간 **자동 리포트**(PDF·Excel·이메일) 및 최소 멀티테넌트(고객사·사용자 관리)

## 아키텍처
> 신규 데이터 인프라 구축이 아니라, **2-2~2-5의 산출 데이터**를 **집계 Job → REST API → 콘솔**로 노출하는 구성.

![[2f_운영콘솔아키텍처.svg|686]]

## 데이터 소스 매핑 (2-2 ~ 2-5 → 콘솔)
| 콘솔 기능 | 주 데이터 소스 |
|---|---|
| ① 성과 대시보드 | **2-2** 행동·성과 로그(노출·클릭·전환·매출, 미세행동) + **2-3** HCI 예측 지표(Intent/Friction 등) |
| ② 콘텐츠 개선 이력 ⭐ | **2-5** Optimization Cycle — 1 레코드가 **2-2 반응 · 2-3 생성/예측 · 2-4 A/B 결과**를 이미 집약 |
| ③ A/B Winner 이력 | **2-4** A/B 테스트 결과(통계검정·Winner) |
| ④ 자동 리포트 | **2-2~2-5 종합** |
| ⑤ 고객사·사용자 관리 | 콘솔 자체 메타(테넌트·계정) |

## 구현 기술 (경량 스택)
- **저장**: PostgreSQL 또는 ClickHouse
- **집계**: Python 집계 Job
- **API**: FastAPI REST API
- **프론트**: 웹 대시보드

## 1. 성과 대시보드
고객사·캠페인·콘텐츠·Variant별로 핵심 지표를 보여준다.

| 구분 | 지표 | 출처 |
|---|---|---|
| **광고 성과** | 노출수 · 클릭수 · CTR · 전환수 · CVR · 매출·ROAS | 2-2 (광고성과·전환/구매 로그) |
| **HCI 행동 지표** | 평균 체류시간 · CTA 망설임시간 · 상호작용 깊이 · 스크롤 깊이 · 이탈률 | 2-2 (JS Tracker 미세행동) |
| **AI 예측 지표** | 평균 Intent · Interest · Friction · Drop-off + 주요 기여요인(SHAP Top-K) | 2-3 (HCI Encoder+예측) |

- **필터(최소)**: 기간 · 고객사 · 브랜드 · 캠페인 · 콘텐츠 · Variant

## 2. 콘텐츠 최적화 이력 조회 ⭐
2-5에서 저장한 **Optimization Cycle**을 사람이 확인하는 화면. **일반 광고 대시보드와 달리 "어떻게 개선됐는지"까지 추적**하는 것이 본 콘솔의 가장 중요한 차별점이다.
> 1 Cycle 레코드는 이미 **2-2 사용자 반응 · 2-3 개선 생성/예측 · 2-4 A/B 검증**을 하나로 묶고 있어(→ [[2e.(3차년도) 행동메모리자산화-콘텐츠생성]]), 콘솔은 이를 사람이 보기 좋게 펼쳐 준다.

`브랜드 담당자 초기 입력 → Baseline 콘텐츠 → 사용자 HCI 반응(2-2) → HCI 예측(2-3) → LLM 개선 Variant(2-3) → A/B 테스트 결과(2-4) → Winner 콘텐츠`

한 캠페인을 선택하면 아래처럼 비교해서 보여준다.

| 구분 | Baseline | Variant A | Winner | 출처 |
|---|---|---|---|---|
| 카피 | 기존 카피 | 혜택형 카피 | 혜택형 카피 | 2-3 생성 |
| CTA | 구매하기 | 할인받기 | 할인받기 | 2-3 생성 |
| CVR | 3.1% | 4.2% | 4.2% | 2-4 A/B |
| Friction | 0.68 | 0.49 | 0.49 | 2-3 예측 |

## 3. A/B 테스트 결과 및 Winner 이력
**2-4 모듈의 결과를 조회·관리하는 수준**(복잡한 실험 설계 기능을 콘솔에서 새로 개발하지 않음).
- 실험 상태 · Control/Variant · 트래픽 배분 · 주요 평가 지표 · 성과 차이 · 통계적 신뢰도 · Winner
- **Winner가 다음 생성에 반영됐는지** 확인 (2-5 Cycle의 "다음 생성 피드백"과 연결):

> 2028-05-12 · Variant B Winner · CVR +14.2% · **다음 생성 Context에 반영 완료**

## 4. 자동 리포트
콘솔 데이터(2-2~2-5 종합)를 정해진 형식으로 자동 정리한다.
- 일간·주간·월간 성과 요약
- 캠페인별 CTR·CVR·ROAS
- 주요 HCI 행동 변화 (2-2 / 2-3)
- A/B Winner (2-4)
- Baseline 대비 개선율

**제공 방식(초기)**: PDF 또는 Excel 다운로드 · 이메일 정기 발송
(Webhook·GraphQL·다양한 외부 연동은 초기 범위에서 제외)

## 5. 기본 고객사·사용자 관리 (최소 멀티테넌트)
"Enterprise" 표현을 유지하기 위한 최소한의 멀티테넌트 기능.
- 고객사별 데이터 분리
- 사용자 계정 관리
- 관리자 / 일반 조회자 권한
- 브랜드·캠페인 등록 및 조회

(복잡한 조직도·세부 RBAC·승인 워크플로는 제외)
