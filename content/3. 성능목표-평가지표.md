




## 6대 정량 성능 목표
| # | 평가 항목(주요성능) | 단위 | 비중 | 세계 최고수준 | 목표치 |
|---|---|---|---|---|---|
| 1 | HCI 기반 전환 가능성·**구매의도 분류** 성능 | F1-score % | 20% | 네덜란드/Univ. of Amsterdam (식별 고객 F1 96.20%) | **F1 80% 이상** |
| 2 | HCI 기반 **프러스트레이션·이탈징후 탐지** | ROC-AUC | 15% | 미국/UT Austin ≈ 91% | **ROC-AUC 0.85 이상** |
| 3 | **인터랙티브 콘텐츠 생성·코드 합성** 성공률 | Accuracy % | 15% | 미국/ChatGPT 5 = 89.7% | **95%** |
| 4 | **레이아웃 재현율 + 인터랙션 동작** 통과율 | 재현율%/E2E% | 15% | 글로벌/Design2Code 88.6–95% | **재현율 85%↑ / E2E 97%↑** |
| 5 | **HCI 이벤트 수집률·데이터 무결성** | 수집률%/유실률% | 15% | 프랑스/Contentsquare(미공개) | **수집률 95%↑ / 유실률 1%↓ / 중복률 1%↓** |
| 6 | **A/B 테스트 통계 신뢰성·오탐률** | FPR % | 20% | 미국/Optimizely 5% | **FPR 5% 이내** |

> 목표 설정 근거: 세계 최고 수준은 대부분 **고객 이력 포함** 조건 → 본 과제는 **익명·세션 기반 HCI Feature** 기준의 현실적 목표. (초기 룰 기반 → 라벨 축적 후 ML 고도화)

## 평가 방법 / 환경
| # | 평가 방법 | 평가 환경 |
|---|---|---|
| 1 | 세션 단위 전환 분류 후 Test Set F1 | 자사 앱/웹·랜딩·HTML5 로그, 익명 세션, Python/PyTorch |
| 2 | Rage/Dead Click·반복 클릭·스크롤 역주행 라벨 기반 ROC-AUC | JS Tracker 삽입 테스트 페이지, 실제 로그 + QA 시나리오 |
| 3 | 프롬프트→생성·빌드·미리보기·ZIP·정책검수 통과율 | 생성 서버, Node.js 빌드, Headless Chrome |
| 4 | 기준 템플릿 대비 위치 일치율 + Playwright/Appium E2E | Chrome/Safari/Edge, Android WebView, iOS WKWebView |
| 5 | 기대 이벤트 대비 수집률·유실률·중복률·스키마 검증 | JS Tracker/SDK, 수집 서버, PostHog/Snowplow 또는 자체 |
| 6 | A/A 테스트 반복 후 FPR 산출 | A/B 엔진, 실험 로그 DB, 파일럿+시뮬레이션 |

## 주요 산식
- 구매의도 F1 = `2·P·R/(P+R)`
- 이탈징후 = 정상 vs 이탈 ROC Curve 면적
- 생성 성공률 = 통과 건수 / 전체 생성 요청 × 100
- 레이아웃 재현율 = UI 요소 위치·크기 일치율 (또는 **mean IoU**)
- 인터랙션 통과율 = E2E 통과 시나리오 / 전체 × 100
- 수집률 = 실제 수집 / 기대 × 100, 유실률 = 미수집 / 기대 × 100
- A/B 오탐률(FPR) = 잘못 Winner 선언된 A/A 실험 / 전체 A/A × 100
