## 지표별 평가 산식

**1. 콘텐츠 생성·빌드 성공률** (①)
$$\text{성공률}(\%) = \frac{\text{빌드·검증 통과 건수}}{\text{전체 생성 요청 건수}} \times 100$$
- 통과 정의: 명세(JSON) → HTML5 빌드 성공 **AND** 스키마·렌더 검증 통과
- 측정: 생성 서버 + Node.js 빌드 + Headless Chrome

**2. 레이아웃 재현율 / 인터랙션 E2E 통과율** (①)
$$\text{재현율} = \text{mean IoU} = \frac{1}{N}\sum_{i=1}^{N}\frac{\text{요소}_i\text{ 교집합 영역}}{\text{요소}_i\text{ 합집합 영역}}$$
$$\text{E2E 통과율}(\%) = \frac{\text{통과 시나리오 수}}{\text{전체 E2E 시나리오 수}} \times 100$$
- 측정: 기준 템플릿 대비 요소 위치·크기 IoU / Playwright(Web)·Appium(App)

**3. HCI Encoder 표현 품질** (②)
$$\text{품질} = \text{ROC-AUC}\big(\text{linear probe}(\text{freeze}(z_{\text{SSL}}))\big)$$
- SSL 사전학습 인코더를 **freeze** → 표현 $z$ 위에 **선형 probe**만 학습 → downstream(전환/이탈) 예측의 ROC-AUC
- AUC = ROC 곡선 아래 면적 = $P(\text{양성 점수} > \text{음성 점수})$

**4. Intent/Friction 예측** (②)
$$F1 = \frac{2 \cdot P \cdot R}{P + R}, \quad P=\frac{TP}{TP+FP}, \quad R=\frac{TP}{TP+FN}$$
$$\text{이탈징후 AUC} = \text{ROC 곡선 아래 면적 (정상 vs 이탈 구분력)}$$
- 측정: 세션 단위 구매의도 분류 F1 / Rage·Dead Click·반복 클릭 라벨 기반 AUC

**5. 생성 신뢰·준수** (③)
$$\text{Schema 유효율}(\%) = \frac{\text{스키마 검증 통과 생성물}}{\text{전체 생성물}} \times 100$$
$$\text{브랜드 준수율}(\%) = \frac{\text{브랜드 룰 통과 생성물}}{\text{전체 생성물}} \times 100, \quad \text{금지표현 위반율}(\%) = \frac{\text{금지표현 포함 생성물}}{\text{전체 생성물}} \times 100$$
- 측정: JSON Schema Validator(pydantic/jsonschema) + 브랜드 룰·금지표현 검수(룰/LLM 판정)

**6. 버티컬 어댑터 라우팅 정확도** (③)
$$\text{정확도}(\%) = \frac{\text{올바른 어댑터로 라우팅된 건수}}{\text{전체 요청 건수}} \times 100$$
- 정답 = 입력 `vertical` 라벨과 선택 어댑터 일치. Cold Start 규칙 라우팅은 결정적(100%), Learned Router는 혼동행렬로 측정

## 부록 · 지표 개정 요지 (보고용)
기존 6대 지표를 **핵심 3개 모듈 기준 6개로 재편**했다. 아키텍처 변경 — (a) HCI Encoder **SSL 사전학습**, (b) rule-based **Policy 제거 → LLM이 Blueprint 직접 생성**, (c) 출력을 **구조화 콘텐츠 명세(JSON Schema)** 로 고정 — 에 맞춰 정합시켰고 **기존 목표치는 손대지 않았다.**

- **유지·재배치**: 구매의도 F1·이탈 AUC(→ ② #4) · 생성 성공률(→ ① #1) · 레이아웃 재현+E2E(→ ① #2) — 목표 동일
- **신규**: ② #3 인코더 SSL 표현 품질 · ③ #5 생성 신뢰·준수 · ③ #6 어댑터 라우팅
- **핵심 KPI에서 제외**: 데이터 수집·무결성 / A/B FPR → 상시 **운영·품질 지표**로 별도 관리(핵심 성능목표 외)
