# (3) 성능 목표 · 평가 지표

> 핵심 3개 모듈(**① 콘텐츠 생성·패키징 엔진 · ② HCI Encoder+MLP · ③ 버티컬 QLoRA**)을 중심으로 정량 지표를 구성하고, 데이터 수집(2-2)·A/B(2-4)를 지원 지표로 둔다.
> 목표치는 **익명·세션 기반 HCI Feature** 라는 본 과제 조건을 반영한 **현실적·달성 가능 수준**으로 설정한다. (세계 최고수준은 대부분 고객 이력 포함 조건)

|---|---|---|---|---|---|---|

## 모듈별 지표 의미
- **① 생성엔진**: "명세대로 실행 가능한 콘텐츠가 실제로 나오는가" — 생성 성공률·레이아웃 재현·인터랙션 동작으로 검증.
- **② HCI Encoder + MLP**: 인코더는 **표현 품질(SSL frozen probe·라벨 효율)** 로, 예측 Head는 **Intent F1 / Friction·Drop-off AUC** 로 분리 평가 → 표현학습과 예측기의 기여를 각각 확인.
- **③ 버티컬 QLoRA**: "구조가 깨지지 않고(Schema), 브랜드를 지키며(준수·금지표현), 업종에 맞게(라우팅) 생성되는가".

## 평가 방법 / 환경
| # | 평가 방법 | 평가 환경 |
|---|---|---|
| 1 | 명세→생성·빌드·미리보기·검증 통과율 | 생성 서버, Node.js 빌드, Headless Chrome |
| 2 | 기준 템플릿 대비 위치·크기 일치율(mean IoU) | 렌더 캡처 비교, OpenCV/스크립트 |
| 3 | 시나리오 기반 E2E 통과 | Playwright(Web) / Appium(App) |
| 4 | SSL 사전학습 후 **인코더 freeze + 선형 probe** 학습해 downstream ROC-AUC | Python/PyTorch, 익명 세션 로그 |
| 5 | 라벨 10% vs 100% 학습 성능 비교(유지율) | 동일 Test Set, 반복 측정 |
| 6 | 세션 단위 구매의도 분류 후 Test Set F1 | 자사 앱/웹·랜딩 HTML5 로그, 익명 세션 |
| 7 | Rage/Dead Click·반복 클릭·스크롤 역주행 라벨 기반 ROC-AUC | JS Tracker 테스트 페이지, 실 로그 + QA 시나리오 |
| 8 | 생성 결과의 JSON Schema 검증 통과율 | Schema Validator(pydantic/jsonschema) |
| 9~10 | 브랜드 규칙·금지표현 룰/LLM-판정 검수 통과율·위반율 | 브랜드 가이드 룰셋 + 검수 스크립트 |
| 11 | vertical 라벨 대비 어댑터 선택 정확도 | Router 로그, 혼동행렬 |
| 12 | 기대 이벤트 대비 수집률·유실률·중복률·스키마 검증 | JS Tracker/SDK, 수집 서버 |
| 13 | A/A 테스트 반복 후 FPR 산출 | A/B 엔진, 실험 로그 DB, 파일럿+시뮬레이션 |

## 주요 산식
- 생성 성공률 = 통과 건수 / 전체 생성 요청 × 100
- 레이아웃 재현율 = UI 요소 위치·크기 일치율(**mean IoU**)
- 인터랙션 E2E 통과율 = 통과 시나리오 / 전체 × 100
- 인코더 표현 품질 = SSL 사전학습 표현 **freeze** 후 선형 probe의 downstream ROC-AUC
- 라벨 효율 = (라벨 10% 학습 성능 / 라벨 100% 학습 성능) × 100
- 구매의도 F1 = `2·P·R/(P+R)`
- 이탈징후 = 정상 vs 이탈 ROC Curve 면적(AUC)
- Schema 유효율 = 스키마 통과 생성 / 전체 생성 × 100
- 브랜드 준수율 = 규칙 통과 생성 / 전체 × 100, 금지표현 위반율 = 위반 생성 / 전체 × 100
- 라우팅 정확도 = 올바른 어댑터 선택 / 전체 × 100
- 수집률 = 실제 수집 / 기대 × 100, 유실률 = 미수집 / 기대 × 100
- A/B 오탐률(FPR) = 잘못 Winner 선언된 A/A 실험 / 전체 A/A × 100
