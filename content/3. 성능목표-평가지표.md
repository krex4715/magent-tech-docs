# (3) 성능 목표 · 평가 지표

> 핵심 3개 모듈(**① 콘텐츠 생성·패키징 엔진 · ② HCI Encoder+MLP · ③ 버티컬 QLoRA**)을 중심으로 정량 지표를 구성하고, 데이터 수집(2-2)·A/B(2-4)를 지원 지표로 둔다.
> 목표치는 **익명·세션 기반 HCI Feature** 라는 본 과제 조건을 반영한 **현실적·달성 가능 수준**으로 설정한다. (세계 최고수준은 대부분 고객 이력 포함 조건)

## 모듈별 정량 성능 목표
| 모듈 | # | 평가 항목(주요성능) | 단위 | 비중 | 세계 최고수준 (참고) | 본 과제 목표치 |
|---|---|---|---|---|---|---|
| **① 생성엔진** (2-1) | 1 | 콘텐츠 생성·빌드 성공률 (명세→HTML5 빌드·검증 통과) | Accuracy % | 10% | 상용 코드생성 ~90% | **95% 이상** |
| | 2 | 레이아웃 재현율 (기준 대비 위치·크기 일치, mean IoU) | 재현율 % | 5% | 글로벌/Design2Code 88.6–95% | **85% 이상** |
| | 3 | 인터랙션 동작 E2E 통과율 (Playwright/Appium) | E2E % | 5% | — | **97% 이상** |

| | 9 | 브랜드 가이드·톤앤매너 준수율 | % | 10% | — | **90% 이상** |
| | 10 | 금지표현 위반율 | % | 5% | — | **1% 이하** |
| | 11 | 버티컬 어댑터 라우팅 정확도 (Cold Start 규칙 100% / Learned Router) | % | 5% | — | **90% 이상** |

| | 13 | A/B 테스트 통계 신뢰성·오탐률(FPR) | FPR % | 10% | 미국/Optimizely 5% | **5% 이내** |

## 모듈별 지표 의미
- **① 생성엔진**: "명세대로 실행 가능한 콘텐츠가 실제로 나오는가" — 생성 성공률·레이아웃 재현·인터랙션 동작으로 검증.
- **② HCI Encoder + MLP**: 인코더는 **표현 품질(SSL frozen probe·라벨 효율)** 로, 예측 Head는 **Intent F1 / Friction·Drop-off AUC** 로 분리 평가 → 표현학습과 예측기의 기여를 각각 확인.
- **③ 버티컬 QLoRA**: "구조가 깨지지 않고(Schema), 브랜드를 지키며(준수·금지표현), 업종에 맞게(라우팅) 생성되는가".

## 평가 방법 / 환경
| # | 평가 방법 | 평가 환경 |
|---|---|---|
| 1 | 명세→생성·빌드·미리보기·검증 통과율 | 생성 서버, Node.js 빌드, Headless Chrome |
| 2 | 기준 템플릿 대비 위치·크기 일치율(mean IoU) | 렌더 캡처 비교, OpenCV/스크립트 |
| 3 | 시나리오 기반 E2E 통과 | Playwright(Web) / Appium(App) |
| 4 | SSL 사전학습 후 **인코더 freeze + 선형 probe** 학습해 downstream ROC-AUC | Python/PyTorch, 익명 세션 로그 |
| 5 | 라벨 10% vs 100% 학습 성능 비교(유지율) | 동일 Test Set, 반복 측정 |
| 6 | 세션 단위 구매의도 분류 후 Test Set F1 | 자사 앱/웹·랜딩 HTML5 로그, 익명 세션 |
| 7 | Rage/Dead Click·반복 클릭·스크롤 역주행 라벨 기반 ROC-AUC | JS Tracker 테스트 페이지, 실 로그 + QA 시나리오 |
| 8 | 생성 결과의 JSON Schema 검증 통과율 | Schema Validator(pydantic/jsonschema) |
| 9~10 | 브랜드 규칙·금지표현 룰/LLM-판정 검수 통과율·위반율 | 브랜드 가이드 룰셋 + 검수 스크립트 |
| 11 | vertical 라벨 대비 어댑터 선택 정확도 | Router 로그, 혼동행렬 |
| 12 | 기대 이벤트 대비 수집률·유실률·중복률·스키마 검증 | JS Tracker/SDK, 수집 서버 |
| 13 | A/A 테스트 반복 후 FPR 산출 | A/B 엔진, 실험 로그 DB, 파일럿+시뮬레이션 |

## 주요 산식
- 생성 성공률 = 통과 건수 / 전체 생성 요청 × 100
- 레이아웃 재현율 = UI 요소 위치·크기 일치율(**mean IoU**)
- 인터랙션 E2E 통과율 = 통과 시나리오 / 전체 × 100
- 인코더 표현 품질 = SSL 사전학습 표현 **freeze** 후 선형 probe의 downstream ROC-AUC
- 라벨 효율 = (라벨 10% 학습 성능 / 라벨 100% 학습 성능) × 100
- 구매의도 F1 = `2·P·R/(P+R)`
- 이탈징후 = 정상 vs 이탈 ROC Curve 면적(AUC)
- Schema 유효율 = 스키마 통과 생성 / 전체 생성 × 100
- 브랜드 준수율 = 규칙 통과 생성 / 전체 × 100, 금지표현 위반율 = 위반 생성 / 전체 × 100
- 라우팅 정확도 = 올바른 어댑터 선택 / 전체 × 100
- 수집률 = 실제 수집 / 기대 × 100, 유실률 = 미수집 / 기대 × 100
- A/B 오탐률(FPR) = 잘못 Winner 선언된 A/A 실험 / 전체 A/A × 100

# 부록 · 지표 개정 내역 (개정 전 → 개정 후)

**개정 배경**: 기술 구조를 3개 핵심 모듈(**① 생성엔진 · ② HCI Encoder+MLP · ③ 버티컬 QLoRA**)로 명확화하고, 아래 아키텍처 변경에 평가 지표를 정합시켰다.
- (a) HCI Encoder를 **Self-Supervised로 사전학습**(2-3)
- (b) rule-based **Policy 엔진 제거** → LLM이 Blueprint를 직접 읽어 생성
- (c) 출력을 자유 HTML이 아닌 **구조화 콘텐츠 명세(JSON Schema)** 로 고정

> **기존 지표는 폐기가 아니라 대부분 "유지·재배치"** 했고, 기존에 없던 **인코더 표현학습·QLoRA 생성품질** 항목만 신규 추가했다. (목표치는 기존과 동일하거나 새로 달성 가능 수준으로 설정)

## 개정 전(기존) 6대 지표
| # | 평가 항목 | 목표치 |
|---|---|---|
| 1 | HCI 기반 구매의도 분류 (F1) | F1 80% 이상 |
| 2 | 프러스트레이션·이탈징후 탐지 (ROC-AUC) | 0.85 이상 |
| 3 | 인터랙티브 콘텐츠 생성·코드 합성 성공률 | 95% |
| 4 | 레이아웃 재현율 + 인터랙션 통과율 | 재현 85%↑ / E2E 97%↑ |
| 5 | HCI 이벤트 수집률·무결성 | 수집 95%↑ / 유실 1%↓ / 중복 1%↓ |
| 6 | A/B 통계 신뢰성·오탐률(FPR) | 5% 이내 |

## 개정 매핑 · 사유
| 기존 지표 | 개정 후 | 변경 유형 | 사유 |
|---|---|---|---|
| ① 구매의도 F1 (80%↑) | ② #6 Intent F1 (80%↑) | 유지·재배치 | 목표 동일 · ② HCI Encoder+MLP 모듈로 그룹화 |
| ② 이탈징후 AUC (0.85↑) | ② #7 Friction/Drop-off AUC (0.85↑) | 유지·재배치 | 목표 동일 · ② 모듈로 그룹화 |
| ③ 생성·코드 합성 성공률 (95%) | ① #1 생성·빌드 성공률 (95%↑) | 유지·정정 | "코드 합성"이 **①생성엔진의 HTML 빌드**임을 명확화(③ QLoRA 생성과 혼동 방지) |
| ④ 재현율+통과율(묶음) | ① #2 재현율 / #3 E2E (분리) | 유지·분리 | 성격이 다른 두 지표를 분리 측정 |
| ⑤ 수집률·무결성 | 지원 #12 | 유지·재배치 | 데이터 품질 **지원 지표**로 이동 |
| ⑥ A/B FPR (5%) | 지원 #13 | 유지·재배치 | 실험 신뢰성 **지원 지표**로 이동 |
| — | ② #4 인코더 표현 품질 (SSL frozen probe) | **신규** | Encoder를 SSL로 사전학습하는 구조 반영 — 예측(MLP)과 **분리해 표현학습 자체**를 평가 |
| — | ② #5 라벨 효율 | **신규** | SSL의 핵심 효익(**적은 라벨로 성능 확보 = 라벨링 비용 절감**)을 정량화 |
| — | ③ #8 JSON Schema 유효율 | **신규** | 출력을 **구조화 콘텐츠 명세(JSON)** 로 고정 → 출력 신뢰성이 핵심 품질 |
| — | ③ #9 브랜드 준수율 / #10 금지표현 위반율 | **신규** | Policy 엔진 제거·**LLM 직접 생성** 구조에서 브랜드/금지표현 준수를 생성 결과로 직접 평가 |
| — | ③ #11 어댑터 라우팅 정확도 | **신규** | 버티컬 특화(**Cold Start 규칙 + Learned Router**) 정확도를 지표화 |

> 요약: **기존 6개 = 전부 유지**(재배치·정정·분리) + **신규 6개**(인코더 SSL 2개·QLoRA 생성품질 4개). 기존 목표치는 손대지 않았고, 심사 부담이 큰 변경은 없음.
