# (2-5) 3차년도 · 브랜드 행동 메모리 자산화 + 콘텐츠 생성

## 목표
브랜드별 HCI 행동·성과 데이터를 **행동 메모리(DB)** 로 자산화하고, 이를 검색해 현재 HCI 예측과 결합한 **Blueprint(추론 Context)** 를 구성한 뒤, 이를 **버티컬 QLoRA LLM에 입력해 콘텐츠 명세를 생성**한다.

## 개발 내용
- 고객사·브랜드·아이템·타깃·채널별 HCI 행동+성과 데이터를 연결한 **행동 패턴 DB** 구축
- 브랜드별 최적화 **Cycle 이력**(초기 생성·사용자 반응·개선 생성·검증결과·다음 피드백) 축적
- 과거 Winner/Loser 사례를 검색해 현재 예측과 결합한 **추론 Context 구성** 및 SHAP·IG·성과 Lift 기반 기여요인 추출
- 버티컬 QLoRA LLM으로 Copy·CTA·Layout·Interaction·Template Parameter 기반 **콘텐츠 명세(JSON) 생성**

# A. 데이터 계층 — 자산화

## 1. 분석·리포팅 계층 (HCI 행동 패턴 DB)
행동 데이터 수집(JS Tracker/SDK · Web/App · A/B 로그 · 광고 성과 로그 · 전환/구매 로그)을 적재해 **행동+성과 통합 DB**로 구조화한다.
- **DIM 테이블**: 고객사 / 브랜드 / 아이템 / 타깃 / 채널
- **FACT 행동/성과 DB**: `session_id·creative_id·variant_id` + FK들 + `event_ts·event_type·hci_features(JSON)·metrics(JSON)·is_conversion·revenue`
- **파티셔닝**: `dt(날짜)/client_id/brand_id/channel_id`, **Hot Data**(ClickHouse/Druid) vs **Cold Data**(S3+Parquet)

![[2e_행동패턴DB.svg]]

## 2. 최적화 이력 계층 (브랜드별 최적화 Cycle)
브랜드별 최적화를 **1 Cycle** 단위로 보고, 각 Cycle의 이력을 축적한다.
- **1 Cycle** = 브랜드 담당자 초기 입력 → Baseline 콘텐츠 생성 → 실제 사용자 행동 수집 → HCI 분석 → LLM 개선 Variant 생성 → A/B 테스트로 개선 효과 검증 → 다음 생성에 결과 반영
- **1 Cycle 내 수집 데이터**: 초기 생성정보 · 사용자 반응 · 개선 생성정보 · 검증결과 · 다음 생성 피드백

![[2e_최적화Cycle.svg]]

### 위 1개의 Cycle안에 들어가야하는 정보
1개 Cycle이 **하나의 레코드(record)** 로 저장되며, 
한 레코드는 아래 5개 블록으로 구성된다. (각 블록은 Cycle 단계와 대응)

| 블록 | Cycle 단계 | 세부 필드 |
|---|---|---|
| **① 초기 생성 정보** | 담당자 입력 → Baseline 생성 | 브랜드 담당자의 옵션·상품·이미지·영상 입력 / 브랜드 가이드·금지 표현 / 캠페인 목표·타깃·채널 / 최초 생성된 Baseline 콘텐츠 |
| **② 사용자 반응** | 행동 수집 → HCI 분석 | 클릭·스크롤·체류·망설임·이탈 로그 / Intent·Interest·Friction·Drop-off 예측값 / 주요 기여 HCI Feature |
| **③ 개선 생성 정보** | LLM 개선 Variant 생성 | 사용한 Base LLM·LoRA Adapter 버전 / LLM에 전달한 Context / 생성된 카피·CTA·레이아웃·인터랙션 / 생성된 Variant A·B·C |
| **④ 검증 결과** | A/B 테스트 검증 | Variant별 CTR·CVR·HCI 지표 / A/B 통계 결과 / Winner·Loser / 어떤 콘텐츠 요소가 변경됐는지 |
| **⑤ 다음 생성 피드백** | 다음 생성 반영 | 다음 LLM에 전달할 Winner 패턴 / 실패 패턴 / 유사 상황에서 참고할 과거 사례 |

> 이 레코드가 곧 **B. 브랜드 행동 메모리**의 검색 대상 — ⑤의 Winner/실패 패턴과 과거 사례가 다음 Cycle의 `3-1 Context 구성`으로 되돌아 들어간다.

# B. 브랜드 행동 메모리 검색 및 콘텐츠 생성
> HCI 패턴정보 · A/B 테스트 Winner 정보 등을 구조화하여 **LLM Context에 입력**한다.
> 현재 HCI 예측결과와 고객사·브랜드·아이템·타깃·채널별 과거 Winner·Loser 사례를 결합한 **Blueprint(추론 Context)** 를 구성하고, 이를 버티컬 QLoRA LLM에 입력해 콘텐츠 명세를 생성한다.

## 3-1. Context 구성 (예측 결과 + 과거 메모리 결합)
- **입력(현재 HCI 예측)**: 세션 벡터 z + 예측 점수(Intent 0.72 / Interest 0.61 / Friction 0.74 / Drop-off 0.68)
- **컨텍스트 정보**: 브랜드/고객사 · 아이템/카테고리 · 타깃/세그먼트 · 채널/캠페인 목표
- **브랜드 행동 메모리 검색(Winner/Loser 사례)**: 업종·아이템·타깃·채널·캠페인 목표 **유사도**로 과거 사례 검색

## 3-2. 주요 기여요인 추출 (원인 분석 & 성과 Lift)
- **행동 패턴 기여도 분석**: SHAP + Integrated Gradients → 주요 행동 기여요인 Top-K
  - `cta_hesitation_time +0.218` · `interaction_depth +0.173` · `scroll_stall +0.142` · `dwell_time +0.128` · `rage_click_count -0.186`
- **성과 Lift 분석**: CTR Lift +18% · CVR Lift +22% · Engagement Lift +15% · Drop-off 감소 -18%

## 3-3. 콘텐츠 명세 생성 (버티컬 QLoRA LLM)
- **Blueprint(추론 Context 패키지) = LLM 입력** — **A 데이터 계층 두 곳에서 조회**해 구성:
  - `① 분석·리포팅 계층(HCI 행동 패턴 DB)` → metrics·hci_features → 성과 Lift·기여요인
  - `② 최적화 이력 계층(Cycle 레코드)` → 과거 Winner/Loser·유사 사례
  - + 현재 HCI 예측결과 · 브랜드 가이드/톤앤매너 · 캠페인 목표/KPI · 지원 컴포넌트/템플릿
- **버티컬 QLoRA LLM**: Game / Webtoon / Commerce Adapter
- **LLM 출력 = 콘텐츠 명세(Content Spec)**: Copy · CTA · Layout · Interaction · Template Parameter (→ ① 패키징 엔진이 HTML로 렌더)
