
# (2-4) 2차년도 · A/B 테스트 Winner 추천 모듈


## 목표
콘텐츠 버전(Variant)을 트래픽 분배로 실험하고, 통계적으로 유의한 **고성과 Variant를 자동 추천**한다.

## 개발 내용
- Creative ID·Variant ID 기반 콘텐츠 버전 관리 + **50:50 또는 가중 트래픽 분배**
- CTR·CVR·체류시간·상호작용 깊이 등 성과지표 집계 및 **최소 표본수·통계적 신뢰도 검증**
- 고성과 Variant 자동 추천 + 우수 카피·CTA·레이아웃·인터랙션 요소의 **개선안 도출**

## 아키텍처 (5단계)
![[2차_AB테스트_엔진.png]]



| 단계 | 이름 | 핵심 |
|---|---|---|
| ① | **Experiment Registry & Variant Manager** | Creative/Variant/Campaign/Audience/Channel ID 키 구조, 메타데이터 레지스트리(카피·CTA·레이아웃·인터랙션·에셋·SDK 버전), Control/Variant A·B·C 버전 그래프 |
| ② | **Traffic Allocation Engine** | 요청→할당엔진→Variant 노출, **Stable Hashing**(`bucket = hash(user_id,experiment_id) % 10000`), Equal(50:50)/Weighted(70:20:10), Holdout/Control 그룹, Eligibility 필터, Exposure-First 로깅 |
| ③ | **Event Join & Metric Aggregation** | Join Key(impression/session/variant id), 중복 제거·봇 필터·watermark 처리, Raw Log Store(S3/HDFS/Kafka)→Aggregated Metric Table→Feature Table, CTR/CVR/Avg Dwell 등 지표 산식, 윈도우(시간/일/실험 전체) 집계 |
| ④ | **Statistical Decision Engine** | 최소 표본 체크 → Control vs Variant 비교 → **p-value/CI/Sequential 유의성 검증** → Guardrail 체크 → 상태 업데이트. 상태: RUNNING / INCONCLUSIVE / WINNER / LOSER / STOP. 검정: t-test, Mann-Whitney, Holm-Bonferroni/FDR, SPRT/Pocock 등 |
| ⑤ | **Winner Reasoning & Improvement Action Generator** | Winner 요인 분해(카피/CTA/레이아웃/인터랙션 기여도), Feature Contribution(예: CTA 상단 배치 +2.1%), 패턴 추출, **Winner Recommendation JSON**(winner_variant, uplift, confidence, p_value, winning_factors, next_actions) |



## 피드백 루프
학습 인사이트 → **다음 Variant 생성**으로 연결 (Variant Pool 업데이트). Closed-loop의 판정 단계.




## 데이터 모델 핵심
`experiments`, `variant_registry`, `metric_summary` 테이블 (experiment_id·variant_id·granularity·impressions·clicks·conversions·ctr·cvr·avg_dwell_time·bounce_rate …).

## 구현 노트
Deterministic Hashing, Exposure-First Logging, Event-time vs Processing-time 분리, Idempotent Ingestion(Unique Key), 데이터 품질·이상 탐지 모니터링.
