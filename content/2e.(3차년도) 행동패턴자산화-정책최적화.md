# (2-5) 3차년도 · 브랜드별 HCI 행동 패턴 자산화 + 콘텐츠 정책 최적화


## 목표
고객사·브랜드·아이템·타깃·채널별 행동+성과 데이터를 연결해 **행동 패턴 DB**를 만들고, 브랜드별 **콘텐츠 정책 규칙**을 자동 산출·업데이트한다.

## 개발 내용
- 고객사·브랜드·아이템·타깃·채널별 HCI 행동 및 성과 데이터를 연결한 **행동 패턴 DB** 구축
- 고전환·이탈·망설임 패턴 분석으로 고객사별 **Feature Weight**와 콘텐츠 정책 규칙 산출
- 반복 캠페인 결과를 다음 생성·A/B 테스트에 반영하는 **정책 버전관리·자동 업데이트** 구조

## 아키텍처
![[3차_행동패턴DB_정책엔진.png]]

### 1. 행동 데이터 수집 연계
JS Tracker/SDK · Web/App · A/B 로그 · 광고 성과 로그 · 전환/구매 로그 → **Data Ingestion**(Kafka/Kinesis) → Stream Processing(Flink/Spark) → Raw Log Store(S3/HDFS).

### 2. HCI 행동 패턴 DB (행동+성과 통합 모델)
- **DIM 테이블**: 고객사 / 브랜드 / 아이템 / 타깃 / 채널
- **FACT 행동/성과 DB**: session_id·creative_id·variant_id + FK들 + event_ts·event_type·hci_features(JSON)·metrics(JSON)·is_conversion·revenue
- 파티셔닝: dt(날짜)/client_id/brand_id/channel_id, Hot Data(ClickHouse/Druid) vs Cold Data(S3+Parquet)

### 3. 행동 패턴 분석 엔진
- **3-1 패턴 분류**(고전환/이탈/망설임/탐색): 규칙 라벨링 + Clustering(K-Means/HDBSCAN) → P01 고전환·P02 이탈·P03 망설임·P04 탐색
- **3-2 Feature Weight 산출**: 전환 기여도 기반 Weight 학습(LightGBM/XGBoost) + SHAP Feature 중요도
- **3-3 콘텐츠 정책 규칙 생성**: 의사결정 트리 → IF-THEN Rule 변환 + 우선순위/가중치

### 4. 정책 버전 관리 및 자동 업데이트
- **Policy Repository**(policy_id·client_id·brand_id·feature_weights(JSON)·policy_rules(JSON)·version·status)
- Policy Version Graph(v1.0→v1.1→v1.2, A/B Test·Rollback 분기)
- 자동 업데이트 파이프라인: 신규 데이터 적재→패턴 재실행→Feature Weight 재학습→규칙 재생성→신규 버전→검증 통과 시 배포

### 5. 정책 적용 흐름 (Runtime)
요청 Context 수신 → **Policy API 조회** → 정책 적용(생성 프롬프트/A/B 가이드/개인화 로직) → 결과 로그 수집 → FACT DB.

## 코드 예시 (다이어그램 내)
